# 本地关键帧检测算法说明

本文档通俗说明监帧工坊关键帧筛选的算法原理与参数含义。**所有算法均为
本地传统图像算法实现，只依赖 numpy 与 Pillow，不调用任何云端 AI 接口，
视频帧不会离开用户设备，不存在隐私泄露风险。**

## 一、整体流程

```
视频文件
  │  FFmpeg 按采样帧率均匀抽帧（本地 subprocess 调用）
  ▼
采样帧 PNG（任务临时目录）
  │  1. 解码并缩放到 160x90 分析尺寸
  │  2. 计算灰度矩阵、HSV 色相直方图、亮度指标
  ▼
逐帧比对（帧间差分 + 直方图相交距离）
  │  按灵敏度阈值判定是否为关键帧
  ▼
关键帧集合 → 缩略图 + 时间戳叠加 → 摘要拼接长图
```

## 二、帧间差分法

### 2.1 原理

把相邻（或与上一个关键帧）两张图片缩放到统一的 160x90 灰度图，
像素值归一化到 0-1，计算平均绝对差：

```
diff = mean(abs(gray_current - gray_previous))
```

- `diff ≈ 0`：两帧几乎一致，画面静止；
- `diff` 越大：像素层面的变化越明显，通常对应物体移动或镜头切换。

使用缩小后的灰度图而不是原图，是为了把监控场景中常见的压缩噪声、
噪点影响降到最低，同时显著减少计算量。

### 2.2 为什么和“上一个关键帧”比

如果始终与相邻帧比较，缓慢移动的目标会让每一帧都“略有变化”，
关键帧数量失控。改为与**最近一个已入选关键帧**比较，只有变化累积到
阈值以上才入选新关键帧，摘要密度更合理。

## 三、HSV 颜色直方图比对

帧差法对“颜色整体改变但形状位置不变”的场景（如灯光色温变化、
彩条切换）不够敏感，因此引入色相直方图：

1. 把图片转到 HSV 色彩空间，取色相通道 H；
2. 过滤低饱和像素（黑白灰没有有效色相）；
3. 量化为 32 个箱，归一化得到直方图；
4. 用**直方图相交距离**衡量两帧差异：

```
hist_distance = 1 - sum(min(hist_a[i], hist_b[i]))
```

距离为 0 表示颜色分布完全一致，越接近 1 表示颜色构成差异越大。

## 四、灵敏度档位与阈值对应关系

两个指标任一超过对应阈值即判定为关键帧（OR 关系，避免漏检）：

| 灵敏度 | 帧差阈值 | 直方图距离阈值 | 适用场景 |
|--------|----------|----------------|----------|
| 高 `high` | 0.0015 | 0.02 | 捕捉微小变化，如远处行人、轻微光影移动 |
| 中 `medium` | 0.015 | 0.08 | 默认档位，平衡摘要密度与信息量 |
| 低 `low` | 0.050 | 0.20 | 仅保留大幅场景切换、明显移动目标 |

阈值越低，越容易触发关键帧，因此同一段视频关键帧数量通常满足：

```
高灵敏度 ≥ 中灵敏度 ≥ 低灵敏度
```

阈值基于 0-1 归一化帧差在项目自带模拟素材上标定，具体数值定义在
`app/core/keyframe_engine.py` 的 `SENSITIVITY_PROFILES` 中，可按实际
监控画面特点调整。

## 五、片头静态片段自动跳过

监控录像开头常出现一段长时间无变化画面（例如夜间无人通道）。
算法以第一帧为基准，连续计算后续帧的帧差，只有当帧差超过档位的
`static_threshold`（高/中/低分别为 0.001/0.01/0.03）时，才认为进入
有效内容区间并从该处开始筛选。若整段视频都没有变化，则保留首帧，
保证摘要结果始终非空。

## 六、无效帧过滤规则

全黑、全白帧不包含有效监控信息，过滤规则只看**亮度均值**：

| 类型 | 判定条件 | 含义 |
|------|----------|------|
| 全黑帧 | 亮度均值 < 6（0-255 量程） | 摄像头被遮挡、夜间红外关闭等 |
| 全白帧 | 亮度均值 > 250 | 镜头强光过曝 |

注意：低照度但**包含画面内容**的夜间场景（亮度均值高于全黑阈值）
不会被误删。可通过请求参数 `filter_invalid=false` 关闭该过滤。
若过滤后没有任何有效帧，智能模式会回退保留第一个有效采样帧，
避免任务产出空结果。

## 七、固定间隔抽帧模式

除智能模式外，还提供确定性的固定间隔模式：

- 按 `interval_seconds`（1-300 秒，默认 10 秒）生成时间点序列，
  始终包含第 0 秒首帧；
- 每个时间点通过 FFmpeg `-ss` 精确抽取单帧；
- 该模式不做帧差筛选，全部采样帧直接进入缩略图与拼接环节，
  适合需要保证时间覆盖均匀性的场景。

## 八、时间戳来源与叠加

每个关键帧的时间戳优先按视频真实时间轴计算：

1. 采样帧时间戳 = 采样序号 / 采样帧率（或固定间隔时间点）；
2. 缩略图左上角以 `HH:MM:SS.mmm` 格式叠加黑底黄字时间戳；
3. 字体优先使用系统等宽 TrueType 字体，缺失时回退 Pillow 内置位图字体。

## 九、性能与资源特性

- 分析前统一缩放到 160x90，单帧特征计算为纯 numpy 数组运算；
- 单任务最多处理 300 帧（`MAX_FRAMES`），防止异常长视频占满资源；
- 任务串行执行，避免多任务并行抢占单机 CPU 与磁盘；
- 全部临时帧位于任务独立临时目录，任务结束立即清理（保留周期可配）。

## 十、与 AI 识别方案的边界

本算法只回答“画面是否发生变化、变化有多大”，**不识别**画面中的人、
车、行为等语义内容，因此：

- 不需要模型文件、GPU 与网络服务；
- 不会产生人脸等生物特征数据；
- 结果可解释：每个关键帧都附带 `diff_score`、`hist_distance` 与
  命中原因（`motion_detected` / `scene_change` / `first_valid_frame`
  等），便于核对筛选依据。
